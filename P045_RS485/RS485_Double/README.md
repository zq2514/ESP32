# ESP32 RS485 主从通信

一套基于 ESP32 + 自动收发 RS485 模块的**一主多从**通信程序。主站通过串口命令控制各从站的板载 LED 开关。

> 定位：学习 RS485 通信原理的完整入门示例。代码注释详尽，可直接在此基础上扩展。

## 1. 系统架构

```
                 ┌─────────────────────────┐
                 │        主站 Master       │
                 │  (ESP32 + 串口命令控制)   │
                 └───────────┬─────────────┘
                             │ RS485 总线 (A / B / GND)
        ┌────────────────────┼────────────────────┐
        │                    │                    │
┌───────┴───────┐   ┌───────┴───────┐   ┌───────┴───────┐
│  从站 Slave 1  │   │  从站 Slave 2  │   │  从站 Slave 3  │
│  地址 0x01    │   │  地址 0x02    │   │  地址 0x03    │
│  LED (GPIO2)  │   │  LED (GPIO2)  │   │  LED (GPIO2)  │
└───────────────┘   └───────────────┘   └───────────────┘
```

**职责划分**

| 角色 | 职责 | 主动/被动 |
|------|------|-----------|
| 主站 | 解析用户命令 → 打包成帧 → 发到总线 → 等应答 | 主动发问 |
| 从站 | 监听总线 → 判断地址是否匹配 → 执行命令 → 回应答 | 被动应答 |

关键规则：**一条总线上同时只能有一个主站在"发"**。RS485 是半双工，多人同时说话会互相打架（这就是为什么从站只在被点名时才回话）。

## 2. 硬件接线

### 每块板 → 自己的 RS485 模块

| ESP32 | RS485 模块 |
|-------|-----------|
| 3V3 | VCC |
| GND | GND |
| GPIO17 (TX2) | RX / DI（数据输入） |
| GPIO16 (RX2) | RO / TX（数据输出） |

> 使用的模块是**自动收发**型（内部已处理方向切换），所以**没有 DE/RE 引脚**，接 4 根线即可。

### 模块之间（总线上多个节点手拉手）

```
所有模块的 A 并在一起，所有 B 并在一起，所有 GND 并在一起。
```

- A ↔ A，B ↔ B（**不能交叉**）
- GND 必须共地（多节点可靠通信的关键，只靠各自板子的 GND 不够）

## 3. 通信协议

自定义简单帧协议，定义在 `include/rs485_protocol.h`，主从共用。

### 帧格式（按字节顺序发送）

```
+--------+--------+--------+--------+--------+----------------+-----------+
| SOI1   | SOI2   | ADDR   | CMD    | LEN    | DATA[0..LEN-1] | CHECKSUM  |
| 0xA5   | 0x5A   | 1 字节 | 1 字节 | 1 字节 | LEN 字节       | 1 字节    |
+--------+--------+--------+--------+--------+----------------+-----------+
```

| 字段 | 含义 |
|------|------|
| SOI1/SOI2 | 帧头 `0xA5 0x5A`，用于接收端对齐帧起点 |
| ADDR | 从站地址 `0x01~0xFE`，`0xFF` 广播 |
| CMD | 命令字 |
| LEN | DATA 字节数（0~8） |
| DATA | 数据（可空） |
| CHECKSUM | 从 SOI1 到 DATA 逐字节累加，取低 8 位 |

### 命令字

| 命令 | 值 | 方向 | 数据 | 应答 |
|------|-----|------|------|------|
| 写 LED | `0x01` | 主→从 | `0x00` 关 / `0x01` 开 | 回 `0x81` + 状态 |
| 读 LED | `0x02` | 主→从 | 无 | 回 `0x82` + 状态 |

**应答约定**：从站应答的命令字 = 请求命令字 `| 0x80`（最高位置 1）。这样主站能区分"自己发的请求"和"从站回的应答"。

### 一次完整交互（字节级示例）

用户输入 `on 1`，主站发：`A5 5A 01 01 01 01 xx`
（帧头 A5 5A + 地址 01 + 命令 01 + 长度 01 + 数据 01 + 校验 xx）

从站 1 收后开灯，回：`A5 5A 01 81 01 01 xx`
（命令变 81 = 写命令 + 应答标志，数据回显状态 01）

## 4. 软件结构

```
RS485_Double/
├── platformio.ini          # 环境配置：master / slave_01 / slave_02 / slave_03
├── include/
│   └── rs485_protocol.h    # 协议：帧格式常量 + 组帧/校验函数（主从共用）
└── src/
    ├── main_master.cpp     # 主站：串口命令解析 + 收发
    └── main_slave.cpp      # 从站：接收命令 + 控制 LED
```

### 一条命令的完整数据流

```
用户敲 "on 1"
   │  (USB 控制台, UART0, 115200)
   ▼
主站 loop() 读到这行 → handleLine() 解析出 cmd="on" arg="1"
   │
   ▼
doWrite(0x01, true) → writeLed() → sendCommand() 组帧
   │  (RS485, Serial2, 9600)
   ▼
从站 recvFrame() 收到帧 → 地址匹配 → applyLed(true) → LED 亮
   │
   ▼
从站 sendResponse() 回应答帧
   │  (RS485)
   ▼
主站 recvResponse() 收到应答 → 打印 "OK"
```

### 为什么拆两个串口？

RS485 和 USB 控制台如果共用 UART0，用户敲的字和从站回的数据会挤在同一根接收线上互相干扰。所以：

- **Serial2（GPIO16/17）= RS485**，专管总线
- **Serial（UART0/USB）= 控制台**，专管人机交互

## 5. 关键概念（小白向）

### 什么是 RS485？

RS485 是一种工业现场总线标准，用**两根线（A/B）的电压差**传输数据（差分信号），抗干扰强、传输距离远（可达 1000 米+）。多个设备能并挂在同一对线上。

### 半双工与自动收发模块

- **半双工**：同一时刻只能一个方向通信（要么发、要么收），不能同时收发。
- 普通 MAX485 模块需要额外一根 **DE/RE 控制脚**，手动告诉它"现在要发还是要收"。
- 本项目用的是**自动收发模块**：内部电路自动检测并切换方向，省掉这根脚，代码也因此更简单（只需读写串口）。

### 从站地址

地址是**软件概念**，不是模块自带的。每块从站烧录固件时由 `SLAVE_ADDR` 决定。本项目用 PlatformIO 的 `build_flags` 注入（见 `platformio.ini`），每块从站一个环境、一个唯一地址，**源码不用改**。

### 板载 LED 极性

ESP32 板载 LED 接在 GPIO2。不同板子点亮极性不同：有的低电平亮、有的高电平亮。从站里用 `LED_ACTIVE_LOW` 宏统一处理，换板子只改这一个值。

### 接收状态机

串口数据是一个字节一个字节到达的，且可能夹着噪声。所以接收端不用"读固定长度"，而是**逐字节判断**：

1. 找帧头 `0xA5 0x5A`
2. 读到 LEN 后算出整帧长度
3. 收满后校验帧头/长度/校验和
4. 核对地址和命令是否匹配

这套逻辑在 `recvResponse()`（主站）和 `recvFrame()`（从站）里各实现一遍，是理解"串口协议解析"的核心。

## 6. 如何扩展

### 6.1 添加一块从站（三步，源码不改）

1. `platformio.ini` 加一个环境：
   ```ini
   [env:slave_03]
   build_src_filter = +<main_slave.cpp>
   build_flags = -DSLAVE_ADDR=0x03
   ```
2. `main_master.cpp` 的 `SLAVE_ADDRS[]` 里加地址 `0x03`（供 `on all` 等批量命令使用）。
3. 新模块 A/B/GND 并进总线，烧录 `pio run -e slave_03 -t upload`。

### 6.2 添加一条新命令（如"读温度"）

1. **协议头** `rs485_protocol.h`：加 `#define CMD_READ_TEMP 0x03`（必要时放宽 `FRAME_DATA_MAX`）。
2. **从站** `main_slave.cpp` 的 `switch` 里加 `case CMD_READ_TEMP:`，把数据放进应答帧。
3. **主站** `main_master.cpp`：加一个 `readTemp()` 函数 + 在 `handleLine()` 里加 `if (cmd == "temp")` 分支。

### 6.3 加超时重发 / 离线检测

当前 `writeLed()`/`readLed()` 发一次等一次。可改成"发 3 次，失败记离线"：

```cpp
// 伪代码
for (int i = 0; i < 3 && !ok; i++) {
    ok = recvResponse(...);
}
if (!ok) markOffline(addr);
```

### 6.4 传多字节数据（如传感器数值）

帧格式本身支持 LEN 最多 8 字节。例如读一个 16 位数值：从站把高字节、低字节依次放进 DATA，主站收后 `(data[0] << 8) | data[1]` 拼回来即可。

## 7. 项目迁移

### 7.1 换到别的 MCU（STM32 / Arduino Uno 等）

这套代码的核心是**协议层**（`rs485_protocol.h` 里的组帧/校验函数），它与具体芯片无关。迁移只需替换两处：

1. **串口 API**：`Serial2.begin(...)`、`Serial2.write(...)`、`Serial2.available()`、`Serial2.read()` 换成目标平台的串口函数。
2. **引脚**：`RS485_RX_PIN / RS485_TX_PIN`、`LED_PIN` 改成目标平台的引脚号。

协议头、帧格式、命令字、收发状态机逻辑**原样保留**。

### 7.2 换成 Modbus RTU（工业标准协议）

本项目的自定义协议和 Modbus RTU 思路一致（主从、地址、命令、校验）。若要对接市面标准设备：

- 保留：总线拓扑、串口配置、半双工方向控制。
- 替换：把自定义帧换成 Modbus 帧（帧头 = 地址 + 功能码 + 数据 + CRC16 校验），或用现成的 `ModbusMaster` / `esp32ModbusRTU` 库。
- 本项目的"写 LED"对应 Modbus 的**写线圈 0x05**，"读状态"对应**读线圈 0x01**。

### 7.3 长距离 / 多节点注意事项

- **终端电阻**：总线两端各接一个 120Ω 电阻（A、B 之间），抑制信号反射。短距离实验可省略。
- **偏置电阻**：节点多、线路长时，在总线一端加 A→VCC、B→GND 的上下拉电阻（典型 680Ω），保证空闲时电平确定。
- **波特率**：距离越远、节点越多，波特率应越低（9600 是安全选择）。
- **拓扑**：用**手拉手**（菊花链）布线，避免星形分支造成反射。
